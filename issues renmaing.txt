STORYVERSE - ISSUES REMAINING
=============================

Purpose
-------
These are the six large epic issues remaining to make Storyverse a working,
submission-ready MVP. Related tasks are deliberately grouped into large issues
so the team has fewer issues to track.


ISSUE 2 - COMPLETE AUTHENTICATION, SUPABASE SCHEMA, RLS, AND SEED DATA
=====================================================================

GOAL
Establish a secure, reproducible backend that works from a clean setup.

WORK INCLUDED
- Remove DEV_BYPASS_AUTH.
- Add session-refreshing middleware and protected routes.
- Verify sign-in, sign-out, reload persistence, and unauthorized redirects.
- Expand the database schema for:
  - Projects and members
  - Branches
  - Scenes and scene versions
  - Characters and character versions
  - World facts
  - AI reviews
  - Merge records
  - Assets
  - Activity events
- Enforce one canon timeline per project.
- Correct foreign-key relationships.
- Review views and functions for RLS safety.
- Test RLS with an owner, collaborator, unrelated user, and anonymous access.
- Create two real demo accounts.
- Make seed data idempotent.
- Add base, branched, reviewed, and merged seed stages.

COMPLETE WHEN
- A fresh Supabase project can be configured by following the README.
- Two users see only authorized projects.
- The application loads real database data with fixtures disabled.
- Seed stages can restore any demo state reliably.


ISSUE 3 - IMPLEMENT THE PERSISTENT STORY-CREATION AND COLLABORATION WORKFLOW
============================================================================

GOAL
Make project, scene, branch, editing, and activity operations real and
reload-safe.

WORK INCLUDED
- Persist project creation.
- Persist scene creation.
- Add branch-only scene editing.
- Store every edit as a new scene version.
- Preserve previous versions and show revision history.
- Persist branch creation from a selected scene.
- Copy the correct story history into a new branch.
- Ensure branching never changes canon.
- Attribute changes to the signed-in collaborator.
- Write activity records for every mutation.
- Replace fabricated and memory-only activity.
- Add loading, failure, conflict, and retry behavior.
- Add optimistic-concurrency protection for edits.

COMPLETE WHEN
- A collaborator creates a branch, edits a scene, and reloads without losing
  anything.
- Canon remains unchanged until an approved merge.
- Revision and activity history show who changed what.
- The workflow works using real Supabase data.


ISSUE 4 - COMPLETE CHARACTER STUDIO AND CONTEXTUAL PANEL GENERATION
==================================================================

GOAL
Deliver the create, refine, approve, lock, and reuse character workflow.

WORK INCLUDED
- Upload character images to Supabase Storage.
- Validate upload type and size.
- Persist characters and character versions.
- Connect Character Studio to /api/ai/character-refine.
- Accept a user refinement instruction.
- Show the AI result as an unapplied proposal.
- Add explicit approve and reject actions.
- Persist approved versions only.
- Lock one version as the canonical reference.
- Use the locked reference, canon facts, scene description, and style
  constraints in panel requests.
- Replace the 1x1 fallback PNG and placeholder reference sheets with original,
  usable artwork.
- Clearly label prepared artwork if live image generation remains out of scope.

COMPLETE WHEN
- A user uploads a character, requests refinement, approves it, and locks it.
- Reloading preserves the character and locked version.
- A panel preview visibly uses the locked character and project context.
- The UI never presents prepared artwork as live-generated output.


ISSUE 5 - COMPLETE LIVE GRANITE CONTINUITY REVIEW AND MERGE ASSISTANCE
=====================================================================

GOAL
Prove IBM AI is genuinely used and reachable from the product.

WORK INCLUDED
- Replace raw API-key bearer authentication with IBM IAM token exchange.
- Cache and refresh IAM tokens.
- Set the correct available Granite model ID.
- Add timeout, retry, rate-limit, and typed error behavior.
- Perform and document a real watsonx request.
- Record the model, region, latency, and data sent.
- Connect the visible review UI to /api/ai/continuity.
- Keep deterministic rules responsible for detecting the concrete
  contradiction.
- Use Granite to explain evidence, severity, and proposed fixes.
- Connect /api/ai/merge-assistant.
- Display compatible changes, conflicts, strategies, and trade-offs.
- Label every result as rule, model, both, or fallback.
- Preserve reliable AI_MOCK=true behavior.

COMPLETE WHEN
- A real Granite request succeeds.
- The review screen detects and explains the compass contradiction.
- The merge assistant returns useful strategies.
- AI output remains a proposal and never writes directly to canon.
- The entire demo still works in fallback mode.


ISSUE 6 - COMPLETE VISUAL DIFF AND TRANSACTIONAL SELECTIVE MERGE
================================================================

GOAL
Make human-reviewed merging the final working product action.

WORK INCLUDED
- Compare every canon and alternate scene.
- Mark scenes as unchanged, changed, added, or removed.
- Highlight changed fields including:
  - Dialogue
  - Action
  - Characters
  - Props
  - Emotional beat
  - Location
- Link continuity evidence to affected scenes.
- Allow reviewers to select individual scenes.
- Show exactly what canon will change before confirmation.
- Execute the selected merge in one database transaction.
- Create new canon versions instead of overwriting history.
- Preserve the source branch.
- Record the reviewer, strategy, selected scenes, and explanation.
- Update the branch graph and activity feed.
- Prevent multiple canon branches.

COMPLETE WHEN
- Selecting two of three changed scenes modifies exactly those two scenes.
- The transaction either completes fully or changes nothing.
- Canon history remains readable.
- The graph and activity history update after the merge.
