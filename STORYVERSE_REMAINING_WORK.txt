2. THE DETAIL
=============

R1  PANE ROUTING                                          [x] DONE 28 Jul
    components/shell/workspace-pane.tsx switches on the active tab's kind.
    The rail opens tabs instead of setting a separate `mode`, and its highlight
    is DERIVED from the active tab - two sources of truth for "where am I" is
    how a rail ends up pointing at Characters while a scene is on screen.
    Panes are keyed by tab id so each keeps its own scroll and expand state.

R2  SCENE DETAIL PANE                                     [x] DONE 28 Jul
    components/story/scene-detail.tsx. Structured fields FIRST, prose second -
    props_used and characters_present are what the continuity engine reasons
    over, so they are what a reviewer needs to check.

R3  CANON CONTEXT BUILDER                                 [x] DONE 28 Jul
    lib/ai/canon-context.ts + 9 tests. Canon and branch facts stay in separate
    lists all the way into renderCanonContext's prompt text, which labels them
    "CANON FACTS" and "THIS TIMELINE ONLY (not canon)".

R4  THE RULE ENGINE                                       [x] DONE 28 Jul
    lib/ai/rules.ts. The rule it implements:

        A prop cannot appear in a scene unless whoever holds it is there.

    Possession is tracked across the timeline from world_facts, and the check
    is against props_used vs characters_present - all structured data, no prose
    comprehension. The what-if S4 fires (Wren has the compass but the stranger
    holds it and is not in the scene); canon does not; S5 does not, because
    the stranger IS in that scene.

    Facts are read through a deliberately narrow grammar (a transfer verb plus
    two cast members, or a possession verb plus one). Anything outside it is
    invisible to the engine BY DESIGN - that is the boundary where the model
    takes over, and it is documented rather than hidden.

    The workspace now computes findings on every load (withRuleReviews in the
    project layout) instead of reading the hand-written fixture. Edit a scene's
    props_used and the finding appears or disappears. EXPECTED_FINDING in
    fixtures.ts is now the ORACLE the engine is tested against, not the source.

R5  BRANCH TREE                                           [ ] tier 1, NEXT
    @xyflow/react. Custom node = mini scene card. Hand-computed layout: canon
    on a straight spine, alternates offset in Y. Canon solid 2px accent,
    alternate 1.5px dashed muted. Click a node -> open that scene's tab.
    FILES: components/story/branch-tree.tsx (new)
    DONE: the fork at S2 is legible at 1920x1080 with animation disabled.

3. STANDING RULES
=================

- Nothing outside src/lib/db/ reads data. No client component fetches.
- Only Rahat edits src/lib/types/schemas.ts, and only after saying so.
- Never render raw model text. Zod-parse in, Zod-parse out.
- Every AI-authored surface carries "AI proposal - not applied" and its
  `source`. This is a judged criterion, not decoration.
- Creative vocabulary on screen: Canon, Timeline, Story Proposal, Canon Review,
  what-if. Never "commit", "PR", or "merge conflict".
- A feature is not done until it works on the deployed URL.
